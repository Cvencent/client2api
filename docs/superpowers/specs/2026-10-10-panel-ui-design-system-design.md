# client2api 面板 UI 设计系统与统一交互规格

日期：2026-10-10

## 目标

把 `internal/panel/index.html` 中现有的运维控制台统一为一套安静、精密、信息密度高的“苹果式”工作台视觉与交互。改造重点是层级、材质、间距、控件状态和动效一致性，不改变任何页面、接口、字段、权限、路由策略或业务行为。

目标用户是频繁查看账号池、用量、平台配置、任务运行状态的运维人员。改造后的界面应适合快速扫描数据和连续操作，而不是做成营销页或展示型官网。

## 范围

本次改造覆盖面板内全部主视图：

- 账号池
- 对话测试
- 用量
- 平台告警
- 积分构成
- 客户端
- 任务中心
- 模型与档位
- 平台配置
- 配置
- 运行日志

同时覆盖跨页共享结构：侧栏、顶栏、内容区、统计条、面板块、数据表、筛选工具条、分页、按钮、输入控件、标签、状态点、二级标签、弹窗、保存条、Toast 和日志框。

## 非目标

- 不新增或删除页面。
- 不修改 API 路径、请求方法、请求体、响应结构和字段名。
- 不修改账号选择、平台路由、模型匹配、任务执行、配置保存、导入导出、刷新和签到逻辑。
- 不引入前端框架、构建步骤、外部运行时依赖或网络字体依赖。
- 不重新设计业务信息架构；现有导航名称和视图归属保持不变。
- 不修改已经存在的无障碍语义、快捷键和键盘操作约定。

## 设计方向

### 视觉语言

采用“系统级工作台”风格：中性底色、克制的半透明层次、细边框、柔和阴影、系统蓝交互色。状态颜色只表达状态，不承担装饰。界面保持高信息密度，但通过分组、留白和层级减少视觉噪音。

设计令牌作为唯一视觉来源，所有组件使用语义变量，不在局部组件中散落新的原始颜色值。

### 颜色

保留明暗两套主题，并重新定义语义令牌：

- 背景层级：页面背景、主表面、次级表面、抬升表面。
- 文本层级：主文本、次级文本、弱化文本。
- 边界层级：结构边界、柔性分隔线。
- 交互色：系统蓝、hover、active、soft 背景和可读文本色。
- 状态色：成功、警告、错误、中性，分别提供 soft 背景和可读文本色。
- 材质：顶栏和侧栏使用克制的半透明背景与模糊，仅用于维持层级，不用于装饰。

浅色主题避免纯白大面积铺底；深色主题避免纯黑大面积铺底，并确保正文对比度达到 4.5:1。

### 字体与数字

使用本机系统 UI 字体栈，不加载网络字体。中文优先使用系统中文字体，保证 Windows 和 macOS 都稳定。所有观测值、余额、token、延迟、速率和表格数字使用等宽数字并启用 `tabular-nums`，避免刷新时列宽跳动。

字号层级保持紧凑：正文 14px，次要信息 11.5px 到 12.5px，标题按视图和面板块两级处理。除数据大数外不使用超大标题。

### 空间与形状

使用 4px 和 8px 递增的间距节奏。容器圆角保持克制，卡片、面板和表格容器使用统一半径；按钮、输入框、标签和状态点使用更小一级半径。阴影分为默认、抬升和弹层三档，禁止局部新增任意阴影值。

## 壳层与导航

### 侧栏

保留现有 11 个导航项和顺序。侧栏在桌面端保持固定宽度，背景使用统一的材质层；当前项使用系统蓝软背景、清晰文字和轻微指示强调。hover、focus-visible、active 状态必须一致且可区分。

窄屏继续使用横向可滚动导航带，避免中文导航项被压成竖排。滚动区域不能导致页面出现横向溢出。

### 顶栏

顶栏保持吸顶。页面标题、辅助信息、主题切换、刷新和添加账号保留现有位置关系和可见规则。添加账号仍只在账号池显示，刷新仍对所有视图生效。

顶栏与内容区之间通过柔性分隔和材质层次区分，不使用厚重阴影。

### 内容区

所有 `.view` 使用一致的内边距、最大宽度和底部安全留白。长表格保留局部滚动和粘性表头，不改变表格列、列顺序和操作按钮含义。

## 组件规范

### 按钮

默认按钮、主按钮、幽灵按钮、危险按钮和图标按钮使用统一高度、圆角、描边和状态。主按钮是当前区域唯一的主要动作。hover 只改变颜色、描边和轻微背景，active 使用轻微下压或亮度反馈。禁用态降低对比且不响应 hover。

图标按钮必须保留可访问名称，现有 SVG 图标不更换语义。

### 输入控件

输入框、下拉框和文本域统一背景、描边、圆角、focus 光环和错误态。focus 不使用浏览器默认轮廓，但必须提供清晰可见的自定义焦点样式。错误态保持现有红色语义和关联提示。

### 标签与状态

标签、状态点、健康条、模型 chip、客户端 chip 和筛选 chip 统一尺寸与颜色语义。颜色不能作为唯一状态表达，必须有文字、图标或形状辅助。

### 表格

表格保持现有列、排序、筛选、分页、粘性表头和固定首列行为。视觉上统一表头背景、行高、边界、hover、选中和分组行样式。数字列继续右对齐或居中，文本保持可读截断。

窄屏继续使用现有卡片化或横向滚动策略，不能新增页面级横向滚动。

### 统计条与数据卡

统计条、用量磁贴、积分卡片和图表容器统一圆角、边界、阴影和内部间距。每个数据块只保留一个主数值和一个辅助说明。进入视图时允许一次性轻微淡入或位移动画，不对密集表格做逐行弹跳。

### 二级标签

用量页和任务中心继续使用现有可复用二级标签控制器。标签的外观统一为分段控件式视觉，选中态清晰，键盘方向键、Home、End 和 ARIA 状态保持现有行为。

### 弹窗、Toast 与保存条

弹窗继续使用遮罩层和现有交互流程。遮罩使用适度模糊和足够对比，弹窗使用背景来源方向的轻微缩放与淡入。关闭后不延迟业务动作。

Toast 使用统一材质、边界和语义左侧状态色。错误 Toast 保持 `role="alert"`，普通确认不抢焦点。

保存条继续粘在视口底部，配置页和平台配置页的保存入口不能因视觉改造而消失。任何改动不得把 `.box` 重新改成 `overflow: hidden`。

## 动效规范

动效服务于层级和因果关系，不做装饰性大动画。

- 页面切换：200ms 到 280ms 的淡入和轻微位移，不阻塞导航。
- 二级标签切换：160ms 到 220ms 的淡入和轻微位移。
- 弹窗：进入 220ms 到 280ms，退出比进入更快。
- hover、focus、active：100ms 到 180ms。
- 图表和数据块：进入时只做一次总量级揭示，不做逐项过度编排。

只动画 `transform`、`opacity` 和颜色。禁止通过动画改变 `width`、`height`、`top` 或 `left` 来制造布局跳动。

必须保留 `prefers-reduced-motion: reduce` 支持。在该模式下关闭非必要动画、图表揭示和加载循环，直接呈现最终状态。

## 响应式规范

至少在以下宽度验证：

- 375px：手机或极窄内嵌浏览器。
- 760px：窄屏应用侧栏。
- 1024px：小桌面窗口。
- 1440px：常规桌面。
- 2200px 以上：超宽屏。

验收时不允许出现页面级横向滚动。表格滚动、导航横向滚动和代码块滚动限定在各自容器内。触控目标不小于 44x44px，空间不足时通过扩展命中区而不是压小图标。

## 无障碍与交互约束

- 保留所有现有 `aria-*`、`role`、`tabindex`、`hidden` 和键盘行为。
- 所有可交互元素保留可见 `:focus-visible`。
- 图标按钮保留 `aria-label` 或现有文本替代。
- 颜色语义必须配合文字或形状。
- 弹窗打开后保留现有焦点行为，不能因动画阻塞输入。
- 动效不得延迟业务操作或改变事件触发顺序。
- 黑色或白色纯色不可作为唯一状态色。

## 实施边界

实现集中在 `internal/panel/index.html` 的样式层和少量表现层脚本中。允许增加设计令牌、统一类、动画工具函数和局部结构包装，但不能改变 DOM id、数据字段、渲染函数的数据来源或接口调用。

现有回归测试必须继续通过，尤其是：

- 面板内联 JavaScript 语法检查。
- shell id 完整性和重复 id 检查。
- 保存条粘底检查。
- 启动完成标记检查。
- 二级标签结构和无障碍控制器检查。

如果需要修改 DOM 包裹层，必须保证 `$("#id")`、`getElementById` 和 `querySelector` 的现有引用仍能解析。

## 验收标准

1. 所有 11 个主视图共享同一套视觉令牌和组件状态。
2. 明暗主题下正文、次要文本、边界和交互状态均清晰可辨。
3. 页面切换、二级标签、弹窗、按钮、表格 hover 和 Toast 动效节奏一致。
4. `prefers-reduced-motion: reduce` 下无强制动画。
5. 375px、760px、1024px、1440px 和超宽屏无页面级横向滚动或明显重叠。
6. 账号池表格、模型表格、任务中心、平台配置和日志页在桌面和窄屏均可用。
7. 功能行为、字段、接口、路由策略和保存流程保持不变。
8. `go build ./...`、`go test ./...` 和 `go run ./cmd/capaudit` 通过。
9. 浏览器截图检查覆盖所有主视图、明暗主题、子标签和至少一个弹窗。
10. 不打包、不提交。

## 验证方式

1. 运行 Go 构建、测试和能力审计。
2. 使用本地面板页面做浏览器自动化检查，逐页验证桌面和移动宽度的布局、可见性、滚动和交互。
3. 对关键页面截图做视觉检查，确认没有文本溢出、控件重叠、表格错位或主题对比问题。
4. 在浏览器中切换明暗主题和 `prefers-reduced-motion`，确认状态和动效降级。
