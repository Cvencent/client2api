# OpenAI-compatible 添加账号弹窗优化设计

## 目标

把 `openai-compat` 的“添加账号”弹窗从一组英文技术字段，改成中文、分层、可快速完成的表单。普通用户只需要选择服务商、填写 API Key，并在需要时打开高级设置。

## 用户路径

1. 选择客户端 `openai-compat`。
2. 在基础区域填写：
   - 服务商：输入或从内置服务商建议中选择，仍允许自定义。
   - API Key：密码输入，支持显示/隐藏，并保留服务商控制台链接。
   - 账号备注：只渲染一个备注字段。
3. 普通内置服务商无需填写接口地址，后端继续使用内置 Base URL。
4. 自定义服务商或需要覆盖模型列表时，展开“高级设置（可选）”：
   - 接口地址（Base URL）
   - 模型列表（Models）
5. 点击“添加”，按钮进入加载状态；成功后清空并刷新账号池，失败时把错误显示在字段附近和弹窗错误区。

## 界面结构

```text
服务商 *                    [输入框 / 内置建议]
说明：选择内置服务商可自动使用接口地址

API Key *                   [密码框] [显示/隐藏]
说明：到 xxx 控制台创建 Key        [打开获取链接]

账号备注                     [输入框]
说明：不填时默认使用服务商 ID

> 高级设置（可选）
  接口地址                   [输入框]
  模型列表                   [多行输入框]
```

## 实现边界

- 字段 key 保持不变：`provider`、`api_key`、`base_url`、`models`、`label`。
- 后端接口和账号数据格式不变，已有账号、导入、导出不受影响。
- `openai-compat` 的字段标题、占位符、帮助文字统一改成中文。
- `core.FieldSpec` 新增可选 `advanced` 标记，只有 `openai-compat` 的 `base_url`、`models` 设成高级项；面板按标记渲染折叠区，不按客户端名称写死判断。
- `advanced` 缺省为 false，其他客户端字段仍按原顺序平铺展示。
- 模块已经声明 `label` 字段时，隐藏弹窗底部固定的通用 `manLabel`，避免两个备注框。
- 密码字段增加显示/隐藏按钮；实现只作用于动态生成的密码输入框。
- 添加时继续调用现有 `/accounts` 接口，不增加新的保存路径。

## 状态与错误

- 必填项显示 `*`。
- API Key 粘贴时去掉首尾空白；如果中间存在空白，继续由后端拒绝并给出明确错误。
- 保存按钮在请求期间禁用并显示“添加中…”。
- 提交前执行必填和基础格式检查，错误显示在对应字段下方。
- 请求失败时：
  - 弹窗顶部错误区显示失败原因。
  - 无法定位到字段的后端错误仍显示在弹窗错误区，不改后端错误结构。
- 成功时关闭错误状态、清空表单并刷新账号池。

## 测试

- 后端单元测试断言 `AccountFields` 返回中文标题、中文帮助和新占位符，且字段 key 保持不变。
- `core.FieldSpec` JSON 测试覆盖 `advanced` 的缺省和显式 true。
- 面板静态测试断言动态密码字段包含显示/隐藏控件。
- 面板静态测试断言存在“高级设置”容器，并只包裹 `base_url`、`models`。
- 面板静态测试断言声明 `label` 字段时隐藏通用 `manLabel`，未声明时仍显示。
- 执行 `go build ./...` 和 `go test ./... -count=1`。

## 非目标

- 不重做整个添加账号弹窗。
- 不修改其他客户端的字段定义。
- 不修改认证、账号池、导入导出或后端保存格式。
- 本次不打包，不更新 Release。
