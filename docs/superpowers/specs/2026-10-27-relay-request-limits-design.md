# 中转站请求次数限额规则 - 设计

**日期：** 2026-10-27
**状态：** 已实施

## 目标

把中转站目前写死的“每分钟请求数”扩展成用户可在面板里直接填写和组合的请求次数规则。

用户不需要编辑 JSON。面板提供表单，每条规则都可以配置：

- 范围：每个 Key / 整个中转站
- 最多请求次数
- 周期数值和单位：秒、分钟、小时、天
- 重置方式：滚动窗口 / 自然周期 / 首次请求起算
- 自然周期的时区，以及可选的每天重置时刻

多条规则同时生效。例如同一把 Key 可以同时受“每分钟 60 次”和“每 24 小时
100 次”约束，所有规则都通过才允许发往上游。单 Key 规则满了自动换下一把 Key；
整个中转站规则满了才返回忙。

计数必须跨进程重启保留，不能因为重启把已用额度误清零。

## 现状

- `internal/core/sources.go` 的 `SourceConfig` 只有
  `requests_per_minute` 和 `requests_per_minute_per_account` 两个次数字段。
- `clients/openaicompat/source.go` 用内存里的固定窗口执行这两个限制：
  窗口从第一次请求开始，满一个周期后重置。
- 面板的中转站编辑框只有两个分钟输入框。
- 没有 24 小时或每日次数规则，也没有滚动窗口、自然周期、时区或重置时刻。

## 非目标

首版只处理“请求次数”限额，不处理：

- token 数、金额、余额类限额
- 自动读取厂商面板里的已用额度
- 网关全局限流
- 按模型单独配置次数限额

现有的 `max_in_flight` 和 `max_in_flight_per_account` 保持不变，继续表示在途并发。

## 配置模型

新增 `request_limits` 数组。配置示例：

```json
"request_limits": [
  {"scope": "account", "limit": 100, "window": "24h", "reset": "rolling"},
  {"scope": "account", "limit": 60, "window": "1m", "reset": "first"},
  {"scope": "source", "limit": 500, "window": "24h", "reset": "calendar", "timezone": "Asia/Shanghai", "reset_at": "00:00"}
]
```

字段定义：

| 字段 | 说明 |
|---|---|
| `scope` | `account` 表示每把 Key 独立计算；`source` 表示整个中转站共用 |
| `limit` | 周期内最多允许的上游尝试次数，必须大于 0 |
| `window` | Go duration 字符串，例如 `30s`、`1m`、`1h`、`24h`；必须至少为 1 秒 |
| `reset` | `rolling`、`calendar` 或 `first`；省略时默认 `rolling` |
| `timezone` | IANA 时区，例如 `Asia/Shanghai`、`UTC`；`calendar` 规则使用，省略时用服务进程本地时区 |
| `reset_at` | 仅 `calendar` 使用，`HH:MM` 格式，默认 `00:00`；表示每个自然周期的起点 |

校验规则：

- `request_limits` 中每条规则都必须有合法 `scope`、正数 `limit`、至少 1 秒的 `window`。
- `reset` 只能是上述三个值。
- `calendar` 的 `window` 必须能整除 24 小时，保证周期每天在 `reset_at` 重新对齐。
- `timezone` 必须是系统可识别的 IANA 时区。
- 相同 `scope + window + reset + timezone + reset_at` 的重复规则拒绝保存，避免同一条规则出现两个上限。
- 继续使用现有的严格 JSON 解析；未知字段仍然报错。

### 旧配置兼容

现有两个分钟字段继续读取：

- `requests_per_minute` 转成 `source` 范围、`1m`、`first`
- `requests_per_minute_per_account` 转成 `account` 范围、`1m`、`first`

`request_limits` 非空时，以新数组为准，旧字段忽略。面板打开旧配置时自动把旧字段
转成规则行；用户保存后写入 `request_limits` 并移除旧字段。未打开或未保存的旧配置
仍按原行为运行。

空数组且没有旧字段表示不限制。

## 规则语义

### 多条规则

每次准备向上游发请求时，先检查所有适用的规则：

- `account` 规则只检查当前 Key。
- `source` 规则检查整个中转站。
- 所有规则都还有余量时，一次性扣减并持久化，然后才发上游。
- 任意一条规则已满，本次请求不能发出。
- 所有候选 Key 的 `account` 规则都满时，返回 `ErrBusy` 并换 Key。
- `source` 规则满时，直接返回 `ErrBusy`，因为换 Key 也不能绕过。

扣减必须是原子的：不能出现“分钟规则扣了、日规则没扣”的半成功状态。

### 重置方式

- `rolling`：精确滚动窗口。每个请求在发生时刻之后满一个 `window` 才释放额度。
  例如 24 小时 100 次，第 101 次必须等最早那次请求满 24 小时。
- `calendar`：固定自然周期。周期按 `timezone` 和 `reset_at` 对齐。
  例如 `24h` + `Asia/Shanghai` + `00:00` 表示每天北京时间零点重置。
- `first`：固定窗口从该 Key 或中转站的第一次扣减开始，经过一个 `window` 后重置。
  这是现有分钟限制的行为，用于兼容旧配置。

`calendar` 的窗口起点在配置的时区内计算；跨夏令时由 Go 的时区规则处理。
首版不支持自然周或自然月，周/月需求用 `rolling` 或 `first` 配长周期。

### 计数时机

- 只有真正准备发往上游的尝试才计数。
- 本地请求校验失败、账号槽位拒绝、构建请求体失败不计数。
- 上游返回 401、402、429、5xx、网络错误都算一次上游尝试。
- 计数在发上游之前持久化。持久化失败时拒绝本次请求，避免在额度未知的情况下继续打上游。

### 规则变更

- 规则签名相同、只改 `limit` 时保留已用计数；调低上限后立即按新上限阻塞。
- 改 `scope`、`window`、`reset`、`timezone` 或 `reset_at` 视为新规则，使用新的计数状态。
- 规则暂时移除后重新添加，如果签名相同，保留原计数，避免通过删除再加回绕过额度。
- 删除账号时清理该账号的计数；整个中转站删除时保留计数文件，重新创建同 ID 中转站仍能接上。

## 面板交互

中转站编辑框增加“请求次数限额”区域，完全使用表单控件，不提供 JSON 输入框。

每条规则是一行卡片，包含：

- 范围下拉框：`每个 Key` / `整个中转站`
- 每 [数值] [单位] 下拉框：秒 / 分钟 / 小时 / 天
- 最多 [次数] 数字框
- 重置方式下拉框：`滚动窗口` / `自然周期` / `首次请求起算`
- 自然周期时才显示：每天重置时刻 `input[type=time]` 和时区输入框
- 删除按钮

区域底部有“添加规则”按钮。没有规则时显示“未设置请求次数限制”。

新增规则的默认值：

- 范围：每个 Key
- 周期：1 天
- 最多：100 次
- 重置方式：滚动窗口

旧配置打开时，两个分钟字段自动生成两条 `首次请求起算` 的规则，用户可以直接改成
`24 小时`、`100 次`、`滚动窗口` 或 `自然周期`。

保存时前端做基本校验，后端再做最终校验。错误直接显示在对话框内，不能静默丢弃规则。

账号列表至少能显示“限额已满”和可计算的恢复时间，避免用户把限额已满误认为 Key 坏了。
完整的历史用量明细不在首版范围。

## 持久化与热更新

计数文件放在每个中转站自己的数据目录：

```text
data/<source>/request_limits.json
```

文件包含版本号和按规则签名、账号 ID 分组的计数状态：

- `rolling` 保存窗口内请求时间戳
- `calendar` / `first` 保存周期起点和已用次数
- 读取时清理过期时间戳和已删除账号的状态

使用现有的 `core.WriteJSONAtomic` 原子写入。文件缺失表示从未使用；文件损坏时拒绝启用
该中转站的限额状态，并在面板显示错误，避免静默把已用额度当作 0。

配置热更新时保留计数状态；已有流不受影响。计数文件不放入配置 JSON，也不写入账号
凭据文件，导入导出账号包时不会把别人的用量带过来。

## 测试

核心与运行时：

- `request_limits` 解析、默认值、非法 scope/limit/window/reset/timezone 校验
- 旧 `requests_per_minute` 字段转规则
- 滚动窗口精确到期、自然周期按重置时刻到期、首次请求窗口到期
- 多规则叠加时取最严格约束
- 单 Key 规则满时轮换到另一把 Key
- 整个中转站规则满时直接 `ErrBusy`
- 本地失败不扣减，上游失败扣减
- 重启后计数恢复；规则热更新保留计数；计数文件损坏时拒绝启用
- 删除账号清理计数

面板：

- 规则表单可添加、编辑、删除
- 旧配置自动迁移为规则行，保存后旧字段消失
- 自然周期时才显示时区和重置时刻
- 非法数字、非法时长、非法时区有可见错误
- 没有 JSON 文本输入框

验证命令：

- `go build ./...`
- `go test ./...`

## 已确定的取舍

1. 使用规则列表，而不是继续增加 `requests_per_day` 之类的一次性字段。
2. 面板只提供表单输入，JSON 只是落盘格式。
3. 计数落盘，重启不重置；持久化失败时宁可拒绝请求，也不超额打上游。
4. 首版只做请求次数，不把 token、金额和并发混进同一套规则。
5. 保留旧分钟字段兼容，但新面板保存时迁移到 `request_limits`。
