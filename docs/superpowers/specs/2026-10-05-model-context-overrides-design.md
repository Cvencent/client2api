# 模型上下文与最大输出可编辑设计

## 目标

模型页要展示每个模型的上下文窗口和最大输出 token，并允许操作者手动修改。手动值必须持久化、升级不丢，并且最大输出的手动值必须真实影响网关发给上游的 `max_tokens`。

## 优先级

每个字段独立解析，优先级从高到低：

1. 操作者手动覆盖
2. 模块当前从上游或 Extra 得到的值
3. `internal/modelmeta/table.json` 官方预设
4. 未公开

上下文字段和最大输出字段可以来自不同层级，来源必须逐字段展示。

## 持久化

- 文件：`<data_dir>/model_context.json`
- 结构按平台和模型分组，避免模型 ID 中的 `/` 与 map 键冲突。
- 写入使用临时文件加原子重命名，权限尽量为 `0600`。
- 文件损坏时按空覆盖处理并记录告警，不让面板或网关启动失败。
- 删除某个手动值时，该字段回落到上游值或官方预设。

## 面板

- `GET /panel/api/model_context` 返回全部覆盖。
- `POST /panel/api/model_context` 接收批量更新；空值表示删除手动覆盖。
- 模型表里的上下文和最大输出改成数字输入框。
- 每行显示来源：`手动`、`上游`、`预设`、`未公开`。
- 每行有“恢复官方默认”，统一保存按钮一次提交当前页面的改动。
- 保存后立即重新渲染，并明确显示成功或失败。

## 网关

请求未显式携带 `max_tokens` 时，按以下顺序取最大输出：

1. 手动覆盖
2. 模块 `ModelLimitsProvider`
3. `modelmeta.StaticMeta` 官方预设

调用方显式提供的 `max_tokens` 永远优先，网关不得改写。

## 兼容性

- 继续复用 `internal/modelmeta`，不建立平行元数据系统。
- `table.json` 只填写有公开依据的官方值，没有依据的模型保持未公开。
- 现有 zcode 验证码窗口、账号标签和模型修复保持不变。
